# 策略组服务

## 职责与配置

接收节点列表和组配置，按显式成员、来源、名称或协议等条件形成策略组。对外使用类型化配置；兼容 custom_proxy_group 的 INI 语法可作为本服务的输入适配器，不能让后续模块再次解析反引号字符串。

GroupDefinition 包含 groupId、名称、行为类型、成员选择配置和行为参数。测速 URL、间隔、超时、容差属于组行为参数；并非每种组都需要这些字段。行为类型与成员选择方式分开建模，避免把“香港节点”这种选择条件当作组类型。

成员配置使用联合类型：NodeRef、GroupRef、BuiltinActionRef、NodeSelector。选择器可按 sourceId、名称正则或协议匹配，组合方式需显式声明为并集、交集或差集；不能把多个字符串条件默认解释为同一种逻辑。

## 输出契约

ResolvedGroupCollection 返回组集合及每个组的有序成员引用。节点通过 nodeId 引用，其他组通过 groupId 引用，内置动作通过语义动作标识引用。名称仅用于显示和目标投影。

显式成员保持配置顺序；选择器展开保持节点列表顺序；同组重复引用按身份保留首次出现位置。relay 等依赖顺序的类型不允许在输出阶段任意排序。节点名称变化后，已绑定 nodeId 的显式引用仍有效；名称选择器则基于本次输入节点重新求值。

## 校验与能力边界

本模块校验组身份唯一、引用存在、非法自引用及循环、参数形态和空组策略。空组行为显式指定为报错、保留供目标判断或使用明确配置的回退成员；不能默认补 DIRECT 改变流量策略。

本模块表达分组意图；目标是否支持 relay、smart 或特定测速参数，由目标输出服务验证。不能在组解析时因为未来可能输出 Clash 而丢失其他目标需要的信息。

规则服务只需获得可绑定组身份与必要元数据，不需要复制组内节点。规则关联不改变策略组成员。

源码参考：`config/binding.h::from<ProxyGroupConfig>`、`config/proxygroup.h`、`generator/config/subexport.cpp`。原选择器语义见[规则与策略组分析](../05-rules-groups.md)。
