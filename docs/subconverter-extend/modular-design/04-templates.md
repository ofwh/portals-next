# 配置模板

## 职责与输入

配置模板提供目标原生基础配置，保留 DNS、监听端口、日志、实验参数等不由节点、组和规则模块生成的内容。TemplateDefinition 包含 templateId、targetType、可选目标版本约束、内容来源、渲染变量及合并配置。

支持内联内容和受控资源来源；模板渲染与原生文档解析由目标输出服务调用模板能力完成。模板不是独立部署服务，也不重新解释订阅地址、规则集和策略组配置。

原项目 base/config 下 INI 是转换配方，*_rule_base 才指向原生基础配置。本设计把配方中的节点、组、规则配置分配到对应模块，配置模板模块仅承接原生底稿及变量能力。

## 输出与约束

模板能力输出渲染后的目标基础配置及模板身份；目标输出服务将其解析为目标文档。模板变量采用明确的可用变量表，未提供变量的处理策略必须显式；不隐式暴露请求认证信息，也不允许模板任意读取进程环境。

模板声明的 targetType 必须与输出类型匹配。Clash YAML 与 sing-box JSON 应使用各自模板；不能依靠序列化格式转换来推断客户端字段含义。

## 生成区域的归属

模板合并配置需要区分节点、策略组、规则区域，分别声明替换或保留并合并。保留内容时，目标输出服务必须把已有节点和组加入最终符号校验，并检查名称冲突。生成内容不能覆盖模板中相同名字的对象而不报告冲突。

规则区域还需处理终止规则：不得在会提前匹配全部流量的兜底规则后追加原本应生效的新规则。具体位置和规则形式由目标适配器决定。其他字段默认保留，不做全局递归深合并。

模板仅提供原生配置，不负责决定不支持协议的丢弃策略，也不负责创建规则引用的组。

源码参考：`handler/settings.cpp` 的各 rule_base 选择与 `generator/template/templates.cpp`。渲染阶段语义见[模板分析](../01-template.md)。
