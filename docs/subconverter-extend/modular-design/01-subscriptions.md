# 远程订阅服务

## 职责与输入

接收订阅地址和订阅类型，通过 HTTP 获取内容，再由对应解析器转换为统一节点列表。订阅类型描述输入格式，例如 Clash YAML、sing-box JSON、URI 列表或 Base64 包装的 URI 列表；它不等于目标输出类型，也不等于机场或供应商名称。

输入 SubscriptionSource 包含 sourceId、url、format、可选请求头以及获取策略。format 使用明确联合类型；auto 如需支持，应作为显式选项，识别失败不得冒充空列表。批量调用接收有序来源集合，结果保持来源顺序与源内节点顺序，不受 HTTP 完成先后影响。

## 输出契约

返回 NodeCollection：节点列表、来源元数据和诊断。每个节点具有稳定 nodeId、sourceId、名称、协议类型、端点、认证、传输和 TLS 信息。节点名称不要求全局唯一，引用使用 nodeId。稳定身份应基于来源身份和源内身份策略生成，不能仅以显示名为键。

格式解析应从完整配置中提取节点，而不是把源订阅的策略组、路由和 DNS 自动合并到后续模块。sing-box 的 selector/urltest 等聚合 outbound、direct/block 等行为对象不应冒充代理端点；无法独立表示的节点依赖应报告诊断，不能静默截断。

## 处理约束

服务内部封装 HTTP 请求、响应状态和大小限制、内容解码、格式解析、协议归一化及逐节点诊断。订阅类型选择解析器，输出目标不参与输入解析器选择。这与原项目按 target 选择 Mihomo/Legacy 的实现不同，属于明确的重写边界调整。

区分 HTTP 失败、解码失败、格式不匹配、节点字段无效、协议不支持、合法空节点集；批量失败策略显式指定为全部成功或允许部分成功。允许部分成功时必须返回失败来源，不得把失败来源当作成功空订阅。

不自动按名称去重。跨来源去重、rename、Emoji 和业务筛选若被支持，作为服务内显式的节点整理配置，输出名称变化不能改变 nodeId。共享缓存以 URL、影响响应的请求头、解析格式及解析器能力身份区分，并对日志中的认证信息脱敏。

## 与其他模块的边界

策略组服务消费节点和来源索引，不重新请求订阅。目标输出服务消费统一节点，不重跑订阅解析。远程 URL 只作为来源信息保留，不自动输出为客户端 provider。
