# 组合契约与配置归属

## 调用关系

调用方或轻量编排器协调五模块；编排器负责调用顺序、取消和结果传递，不解释协议、选择器或规则语义。公共 HTTP、缓存和日志设施可供多个模块复用，但不是额外业务模块。

| 配置或数据 | 唯一业务归属 | 其他模块的使用方式 |
| --- | --- | --- |
| 订阅地址、输入类型、获取请求头 | 远程订阅服务 | 其他模块消费节点和来源 |
| 节点过滤、rename、Emoji 等可选整理 | 远程订阅服务 | 组服务匹配整理后的节点 |
| custom_proxy_group 对应的组与选择配置 | 策略组服务 | 输出服务消费已解析成员 |
| ruleset 对应的定义、绑定与顺序 | 规则服务 | 输出服务投影目标规则 |
| 规则启用及底稿规则保留意图 | 规则服务 | 输出服务执行目标装配 |
| 原生底稿、模板变量、区域合并配置 | 配置模板 | 输出服务渲染、解析与合并 |
| 输出类型、版本、原生格式能力 | 目标输出服务 | 其他模块保留目标无关数据 |

配置归属表示业务解释权，不表示字段只能在一个调用参数中出现。模板规则合并设置若与规则计划的保留意图冲突，应返回配置冲突，不设置两套隐式优先级。

## 统一数据约定

NodeId、SourceId、GroupId、RuleSetId 使用不同身份类型。协议节点采用带协议标签的联合类型；认证、传输和 TLS 保留明确字段。可选布尔使用未指定/true/false，不能用缺省 false 覆盖源信息。

节点、组成员、规则绑定均保留明确顺序；并发获取不能改变结果顺序。名称允许编辑，身份和关联不依赖名称。每个模块返回结构化诊断，包含模块、对象身份、错误码和必要上下文，来源 URL 中的敏感参数脱敏。

模块接口消费数据快照，避免规则服务或目标输出服务原地修改节点列表。取消、截止时间和资源预算通过共同执行上下文传递；HTTP 客户端作为依赖注入，不由领域模型创建。

## 组合实例

输入一个 Clash YAML 订阅和一个 Base64 URI 订阅。远程订阅服务分别获取并解析，返回统一节点列表；策略组服务定义 AUTO 按节点名称匹配，Proxy 引用 AUTO 和 DIRECT；规则服务定义域名规则集并绑定 Proxy，另设 DIRECT 兜底；输出服务选 Clash 模板后生成 YAML。

同一组业务数据切换为 sing-box 输出时，替换目标类型和匹配的模板，由目标输出服务检查协议、组行为与规则条件能否表示，再生成 JSON。无需重新请求订阅或重新解释配置语法；目标不支持的能力会显式失败，不能保证所有输入均可跨目标无损转换。

## 与原实现的兼容边界

| 原实现行为 | 本设计处理 |
| --- | --- |
| target 决定 Mihomo/Legacy 输入解析器 | 按输入订阅类型和解析能力选择，输出目标独立 |
| Clash 等目标默认保留客户端远程资源 | 核心链路统一服务端获取实际节点 |
| INI 配方混合节点、组、规则和底稿设置 | 由兼容适配器拆给各模块配置；领域服务不解析整份配方 |
| 原生规则 provider 与客户端刷新 | 不作为核心规则契约；需扩展时明确资源执行方 |
| 原绑定器部分无效项被跳过 | 新接口返回诊断；是否允许跳过由显式兼容策略决定 |

后续单模块拆解应在对应专题中描述其内部数据流，其他四个模块仅作为端点。总览保持五模块粒度，不把 HTTP 解码、正则匹配或字段序列化提升为同级服务。
