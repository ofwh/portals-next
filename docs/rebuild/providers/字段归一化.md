# ProxyNode 字段归一化

URI 解析器返回带协议判别字段的协议节点，可保留协议自身的层级结构。协议节点仅用于 providers 内部解析与转换，不作为工作流输出。

`transform` 将协议节点转换为公共 `ProxyNode`。公共节点是完全扁平的数据对象，字段值仅使用字符串、有限数字、布尔值及基础值数组，不包含嵌套对象、对象数组或 `undefined`。未提供的可选字段省略，显式 `false` 和 `0` 保留。

## 字段语义

- 字段按作用归一化，不按 URI 参数拼写或所属协议直接拼接层级。名称不同但语义一致的凭据、加密方式、传输及公共选项使用同一字段；不同含义的 UUID、密码、令牌及私钥分别保存。
- TLS 启用状态与 TLS 选项位于顶层。传输 Host 与 TLS 服务名称分开；Reality 公钥与 WireGuard 公钥分开；协议令牌与 Realm 令牌分开。
- 归并时核对单位、默认值与有效范围，不能仅因名称相似而合并。协议专属但无法共享语义的字段使用明确名称，不保留协议对象包装。
- 端口范围使用有序字符串数组，单端口与范围分别表示。端口范围对应的传输数组与范围数组逐项对应，顺序和长度一致。
- 插件名与选项分开保存。选项使用有序字符串数组，开关保留键，带值选项保留键和值；仅按第一个等号拆分。
- WireGuard URI 表达一个远端 peer，转换后远端端点、密钥及选项直接保存在顶层，本地地址及 DNS 使用字符串数组。

公共节点字段以 `lib/subscription/types/` 的类型为准，运行时校验维护在 `lib/subscription/schemas/`；协议解析模型以 providers 的类型为准。新增协议字段须同步更新解析模型、转换和公共 schema，不能通过动态字段透传绕过公共数据契约。

## 协议节点与公共节点映射

以下映射约束 `ProviderNode → ProxyNode` 的转换及反向组装。左侧路径相对于协议解析结果，右侧路径相对于公共节点；表中列出的同名字段按名称逐一对应。反向组装须先根据 `protocol` 选择协议类型，再应用公共映射和该协议的专属映射，不根据可选字段猜测协议。

### 公共字段

| 协议节点路径                                                         | ProxyNode 字段                                        | 还原约束                                                      |
| -------------------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------- |
| `protocol`、`name`、`server`、`port`                                 | 同名字段                                              | 协议判别、名称及端点直接保留；WireGuard 端点规则见下文        |
| `sourceId`、`sourceGroup`、`sourceGroupId`                           | 同名字段                                              | 仅在提供时保留，由调用层补充来源信息                          |
| `username`、`password`、`uuid`、`token`                              | 同名字段                                              | 仅适用于拥有对应凭据的协议；Hysteria 的密码来源见专属映射     |

### SS、SSR、VMess、VLESS 与 Trojan

| 协议      | 协议节点路径                                      | ProxyNode 字段                    | 还原约束                                                            |
| --------- | ------------------------------------------------- | --------------------------------- | ------------------------------------------------------------------- |
| SS、SSR   | `method`                                          | `encryption`                      | 按 `protocol` 还原为 `method`，不能同时生成另一个 `encryption` 字段 |
| SS        | `plugin.name`、`plugin.options`                   | `plugin`、`pluginOptions`         | 按插件选项规则还原 `plugin` 对象                                    |
| SSR       | `ssr.protocol`、`ssr.protocolParam`               | `ssrProtocol`、`ssrProtocolParam` | 放回 `ssr` 对象，不覆盖节点的 `protocol`                            |
| SSR       | `ssr.obfs`、`ssr.obfsParam`                       | `obfs`、`obfsParam`               | 放回 `ssr` 对象；`obfsParam` 不等同于混淆密码                       |
| VMess     | `alterId`                                         | `alterId`                         | 直接保留                                                            |
| VLESS     | `flow`                                            | `flow`                            | 直接保留                                                            |
| Trojan-Go | `trojanGo.encryption`                             | `encryption`                      | `protocol` 仍为 `trojan`，存在该字段时放回 `trojanGo` 对象          |

## 集合还原规则

- 端口范围中，`"443"` 还原为 `{ start: 443, end: 443 }`，`"1000-2000"` 还原为 `{ start: 1000, end: 2000 }`。数组顺序保留，不展开范围、不排序、不额外去重。还原后校验端口有效范围及起止顺序。
- Mieru 的范围与传输数组必须等长，按索引配对，不能分别排序。根级 `port` 与首个绑定的起始端口保持一致。
- 插件选项中，`"flag"` 还原为 `{ flag: true }`，`"key=value"` 还原为 `{ key: "value" }`；值可以为空，也可以继续包含等号。字符串 `"key=true"` 的值仍为字符串，不转换为布尔值。插件选项键不包含等号，每个键在选项数组中至多出现一次。
- 其他基础值数组直接保留元素类型和顺序，不拼接成字符串。

## 还原边界

还原目标是协议节点的有效配置语义。当前入口只实现正向转换；反向转换须执行目标协议校验，不得仅凭公共字段存在就认定其组合有效。

- 公共字段缺省时不补可选值，保留 `false`、`0`、空字符串与空数组之间的区别。协议要求的必填值缺失时应报错。
- 嵌套对象的存在性以对应字段及协议约束决定。空对象与完全缺省对象的区别不会被保留；只包含 `undefined` 的对象也不会留下存在标记。
- 原始 URI 的 scheme 别名、参数别名、参数排列、编码方式、外层 Base64 形式以及显式默认值与解析器补入默认值的区别不会被保留，不能据此还原原始 URI 字节。
- Trojan 与 Trojan-Go 共用规范协议标识。Trojan-Go 专属字段存在时可恢复对应配置；仅凭 `protocol: 'trojan'` 无法判定原始 scheme。
- 解析器已完成的名称回退、参数归一化、范围去重及未识别参数丢弃不会由 `transform` 撤销。Mieru 的未知参数标记只能表示存在性，不能恢复原始参数。
- 新增多 peer、保留 URI 原文或区分空包装对象等需求时，应扩展数据契约，不能从当前字段猜测缺失信息。
