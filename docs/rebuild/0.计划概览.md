## 模块处理

将转换拆解为5个模块

- 节点配置
- 分组配置
- 策略配置
- 模板配置
- 编译转换

### 节点配置

节点内容即是订阅的配置文件内容，格式内容为 SS订阅 类型。格式为 `base64(URI[].join('\n'))` 的内容。

节点配置处理过程

1. base64 接码内容
2. 通过 **换行符** 进行分割，得到一行一个的 URI格式的订阅配置 内容
3. 对每一个 URI格式订阅进行解析， 得到原始订阅配置 `ProxyNode` 类型，此类型为 plain 格式的数据对象
   1. 类型需定义好所有可能的可选字段，适配所有已知的类型如 Shadowsocks/ShadowsockR/Trojan/Vless/Vmess/AnyTLS 等等类型
   2. 先整理所有的订阅类型，需通过 **批量勾选** 需要支持的订阅类型列表
   3. 再组合所有已选订阅类型的所有字段，包括可选字段。整理为完整的类型 **ProxyNode**， 其中相同信息但在不同订阅中有不同名称的字段，在ProxyNode类型中合并为一个字段
   4. 过滤不支持的订阅类型（这里假设 mieru 类型不做支持，则解析后若有此类型则忽略）
4. 最后输出转换得到的通用的 `ProxyNode[]` 订阅列表数据

### 分组配置

配置内容为 ini/toml/yml 格式的内容，对应 `/Users/larify/Documents/github/SubConverter-Extended/base/config/example_external_config.{ini|toml|yml}` 中的 `custom_proxy_group` / `custom_groups` / `proxy_groups` 内容。

配置内容需根据 **配置类型** ，结合 **解析类别** 进行内容解析，得到对应的配置 `ProxyGroup[]`

#### 配置类型

ini/toml/yml 配置类型，均不支持 **import** 方式引入，统一使用 **文本内容配置**

根据指定的配置类型，解析后并提取项内容

- `custom_proxy_group`：ini格式
- `proxy_groups`：yaml格式
- `custom_groups`：toml格式

#### 解析类别

根据配置 **类型解析** 并提取对应字段的内容信息后，根据 **解析类别** 对应的解析器 resolver， 对配置信息进行响应的 **解析方法** 进行解析（resolve）

这里的 **解析类别** 以及 **解析方法**，需要先通过对 **应用代码** 阅读后得到对应的类别列表（解析类别），以及对对应类别的解析处理（解析方法）

#### 处理流程

1. 指定 **配置类型** 和 **解析类别**
2. 通过配置类型对输入的配置内容进行解析，并提取对应配置类型的字段内容
3. 通过解析类别指定的解析器，对得到的字段内容进行解析
4. 得到通用的分组配置列表 `ProxyGroup[]`

### 策略配置

与分组配置处理流程类似，通过指定的 **配置类型** 和 **解析类别**， 对配置内容进行解析处理

#### 配置类型

与分组配置处理一致，解析配置后，读取的字段

- `ruleset`: ini格式
- `rulesets`: toml格式 和 yml格式

#### 解析类别

与分组配置处理流程类似，通过选定的 **解析类别** 对应的解析器，对配置进行针对性的解析。需要通过阅读应用代码，得到支持的解析类别，以及对应的解析方法

#### 处理流程

与分组配置相同

1. 指定 **配置类型** 和 **解析类别**
2. 通过配置类型对输入的配置内容进行解析，并提取对应配置类型的字段内容
3. 通过解析类别指定的解析器，对得到的字段内容进行解析
4. 得到通用的分组配置列表 `RuleSet[]`

### 模板配置

模板内容可以是 yml/json 等格式的配置内容，内容格式为最终输出的订阅类型配置格式，

例如

- 输出为 Clash 订阅时，则为 yml 格式的内容
- 输出为 sing-box 订阅时，则为 json 格式的内容

模板内容仅需要通过对应解析器进行解析后无需对内容做任何分析处理，直接以模板对象 `Template<T>` 保存

### 编译转换

根据选定的 **订阅类型** 作为目标 **输出类型**，将前面提供的 `ProxyNode[]` / `ProxyGroup[]` / `RuleSet[]` / `Template` 内容数据进行组合（按照 SubConverter 中的实现方式进行组合）生成最终的订阅内容并输出

输出类型支持以下格式内容，仅需按照参考应用中对以下输出格式的处理进行实现

```ts
const labels: Record<CompileTarget, string> = {
  mixed: 'Mixed',
  clash: 'Clash',
  loon: 'Loon',
  singbox: 'sing-box',
  quanx: 'Quantumult X',
  surge: 'Surge',
  surfboard: 'Surfboard',
  mellow: 'Mellow',
  v2rayn: 'v2rayN',
  v2rayng: 'v2rayNG',
};
```

根据 **输出类型**，决定转换后的目标数据格式：

- 将 ProxyNode[] 转换成目标类型支持的对应节点格式
  - 根据节点类型，按照输出类型支持的格式进行输出
- 将 ProxyGroup[] 转换成目标类型对应的规则格式内容
  - 根据输出类型的目标规则格式进行数据转换
- 将 RuleSet[] 转换成目标类型对应的策略格式内容
  - 根据输出类型的目标数据格式进行转换处理
- 将以上转换后的数据，写入到模板配置数据 Template<T> 中
  - 数据写入遵循 SubConverter-Extended 中默认的 enable_rule_generator=true 和 overwrite_original_rules=false 的参数进行处理。需在服务模块实现时，支持以上参数，并指定参考应用的默认值
  - 遵循参考应用中，在不同输出类型格式下，结合 enable_rule_generator/overwrite_original_rules 参数设定，对数据进行融合处理（未提及的参数，不需要进行逻辑处理和实现）

**一句话总结：将 节点列表，规则配置，策略配置 按照输出类型的格式进行转换后，按照 参考应用 中的实现，再与模板内容进行合并融合处理，最后输出目标输出类型的格式进行输出**

#### 订阅类型处理

根据选择的 **输出类型**，将 ProxyNode[] 节点列表转换为目标类型格式

- 遍历节点列表，过滤掉不支持的节点类型（根据**订阅类型**内部配置的支持的节点类型列表进行过滤），并将支持的节点类型，转换为目标订阅对应的类型格式字段进行输出
- 遍历分组配置，根据分组中的配置，将转换后的节点（节点名称），按照**订阅类型**的输出格式，转换为目标订阅对应的分组类型格式字段，并输出
- 遍历策略配置，根据策略中的配置，结合节点列表+分组配置的内容，按照**订阅类型**的输出格式，转换为目标订阅对应的策略（规则）类型格式，进行输出
- 根据**订阅类型**解析后的模板内容，结合以上输出的目标**订阅类型**对应的 节点列表/分组列表/策略（规则）列表 进行组合（combine）处理（这里每一种订阅类型的组合方式不一样，通过阅读 应用源码 获取到模板处理方式）

#### 规则处理

根据 **输出类型**，将 ProxyGroup[] 规则列表转换为目标规则格式

#### 策略处理

根据 **输出类型**，将 RuleSet[] 策略列表转换为目标规则格式
