# 编译转换

编译请求含目标 ID、四种公共数据及显式编译选项。返回订阅文本、内容类型及脱敏诊断。目标驱动放在编译转换模块的 `drivers` 子目录（`lib/subscription/compile/drivers`）。每个驱动注册可用协议、进一步的节点字段限制、分组和规则能力、模板格式、输出模式及合并策略。驱动范围见[目标清单](drivers.md)。

## 阶段

1. 验证目标与模板格式，拷贝可修改的模板。收集模板里需要保留或预留的名称、内置策略名和已提供的远程资源标识。
2. 筛掉目标无法表示的协议，再用协议和目标版本检查字段组合。对成功编码的节点分配唯一名称并建立身份到最终名称的映射。诊断区分协议不支持、字段不兼容和编码错误。
3. 在成功输出的节点上求值分组选择器。先预留将输出的组名，允许前向组引用。显式引用可指向目标内置策略、有效节点或组。保持成员顺序并去重。空组、缺失引用和循环按目标规则处理，同时校验目标支持的 provider 引用。
4. 按声明顺序绑定规则目标。驱动可编码内联规则或发出目标支持的原生规则集引用。需要展开的资源使用调用层已提供的正文解析结果。最终规则优先级、默认规则和 `no-resolve` 等选项由目标语义决定。
5. 调用驱动合并节点、组、规则和模板，校验最终引用和输出限制后序列化。失败返回诊断，避免返回半份配置。节点列表模式、保留或覆盖原始规则及资源路径均为显式选项。

## 验收

按目标记录同一输入的旧输出和新输出。覆盖禁用协议、受限传输、同名节点/组、节点被滤除后分组和规则的引用、模板无关字段、规则覆盖模式、远程资源无正文时的分支、节点列表输出以及大小上限。模板和规范节点可安全用于重复编译。旧入口只负责交付材料和接收结果。
