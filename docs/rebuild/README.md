## 实现基准

重构以本入口及各模块文档明确约定的行为为准。文档未明确的类型定义、转换方法、处理流程、条件判断、过滤规则及其他实现细节，均以参考应用 SubConverter-Extended 的现有代码为准。迁移时应实现等效行为，保持相同输入和配置下的处理结果一致。 [SubConverter-Extended 源码](/Users/larify/Documents/github/SubConverter-Extended/src)

## 依赖方向

实现目录均相对于当前仓库的 `lib/subscription`。四个输入模块独立工作，仅依赖公共类型和必要的文本工具。编译模块通过数据契约消费输入，分组成员求值、规则目标绑定和模板合并均在编译阶段完成。调用层负责选择格式、解析器、目标和选项，取得文本并决定何时编译。

旧入口的订阅下载、模板预渲染、规则资源获取、请求参数及上传留在调用层或兼容适配层。资源支持范围与规则合并行为统一见[编译转换](compile/README.md)。输入模块与编译核心均可离线运行。旧订阅入口接受的 Clash YAML、sing-box JSON、SSD 等整份配置，和本次要求的 Base64 URI 输入范围有差异，应在迁移时单独登记。

## 落地顺序

1. 批量选择输入协议，核对字段、别名及样例，冻结公共类型的首版范围。
2. 分别用纯文本样例实现四个输入模块，验证排序、默认值、非法项与禁止导入。
3. 按目标逐个提取驱动，先记录旧入口在相同输入下的输出，再验证新驱动的目标语义和引用闭合。目标保留范围与输入协议独立确认。
4. 接入现有转换入口，分目标核对配置合并、节点列表模式、引用闭合及输出限制，再替换旧路径。
