# 国际化

国际化使用 `next-intl`，保持现有 URL，不添加语言前缀。页面与业务 API 的语言选择统一遵循[偏好设置](preferences.md)的读取优先级，仅接受已登记的语言值，最终回落到英文。

- 页面文案使用 ICU 消息格式，以英文资源定义完整消息结构；其他语言缺少的消息按层级合并回落到英文，避免在组件内硬编码可翻译文案。
- 简体中文描述与提示文案默认不以句号结尾，句子之间的标点正常保留。
- 页面消息键的每一层统一使用小驼峰命名，以 `.` 表示嵌套层级，不使用下划线连接单词。
- 业务文案按侧栏功能组及页面路由分层组织。跨模块复用的通用文案放在根级 `shared`；模块内复用的文案放在对应模块的 `shared` 子命名空间。仅合并语义一致的文案，原位置不保留重复定义，调用方直接引用公共命名空间。
- 新增页面语言时，在 `messages/` 增加语言 JSON，并在 `i18n/config.ts` 导入、登记到 `languageMessages`；支持语言与语言选择项由该登记自动生成。API 文案独立维护，未提供对应语言资源时回落到英文。
- 页面接入翻译时，服务端异步组件使用 `getTranslations`，客户端组件使用 `useTranslations`；使用客户端翻译的组件须由 `NextIntlClientProvider` 包裹。
- 同一函数、组件或 hook 中的翻译函数统一命名为 `t`，不使用其他别名。涉及多个命名空间，或完整翻译键仅有两层时，使用不绑定命名空间的翻译函数并传入完整键；仅使用一个深层命名空间时可绑定该命名空间。
- 语言选择依赖请求数据；页面接入时须遵守 Next.js 对请求数据与 Suspense 边界的约束，不得将按请求选择的语言放入跨请求共享缓存。
- API 错误文案继续遵循 [API 规范](api.md)，不混入页面文案。
